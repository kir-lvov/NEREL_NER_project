# NER на датасете NEREL

Решение задачи извлечения именованных сущностей (Named Entity Recognition) из русского текста с помощью тонкой настройки RuBERT.

---

## Задача

Дана последовательность токенов русского текста. Требуется для каждого токена определить тип именованной сущности или отнести его к классу «не сущность» (O).

**Вход:** строка текста на русском языке.
**Выход:** список найденных сущностей в формате `(начало, конец, тип, текст)`.

**Типы сущностей:** PERSON, ORGANIZATION, LOCATION, DATE, PROFESSION, CITY, COUNTRY, EVENT, LAW, RELIGION.

**Датасет:** [NEREL Short](https://github.com/nerel-ds/NEREL) — 2508 примеров с BIO-разметкой.

---

## Обоснование выбора метода

Для задачи NER на русском языке выбран подход **тонкой настройки предобученной модели RuBERT** (`DeepPavlov/rubert-base-cased`).

**Почему не классический ML (SVM, Random Forest, BiLSTM-CRF):**
- Требуют ручной разработки признаков (морфология, контекстные окна, словари).
- Качество на NER для русского обычно на 10–15% ниже, чем у трансформеров.
- BiLSTM-CRF без предобученных эмбеддингов плохо работает на малых датасетах.

**Почему не few-shot через API (GPT / GigaChat):**
- Высокая стоимость при масштабировании.
- Задержки при инференсе.
- Данные уходят на внешние серверы.

**Почему RuBERT:**
- Лучшее в классе качество для NER на русском.
- Обучен на больших русскоязычных корпусах.
- 2508 примеров достаточно для эффективной тонкой настройки.
- Готовые инструменты Hugging Face → быстрая разработка.
- Воспроизводимость за счёт фиксированного seed.

## Подход

| Параметр | Значение |
|---|---|
| Модель | `DeepPavlov/rubert-base-cased` |
| Задача | Token Classification |
| Dropout | 0.15 |
| max_length | 128 |
| learning_rate | 2.5e-5 |
| Разметка | BIO |
| Метрика | seqeval F1 (macro) |

Метки выравниваются по субтокенам BERT: первому субтокену ставится исходная метка, остальным — `-100` (игнорируются при подсчёте лосса и метрик).

---

## Результаты

**Итоговые метрики на тестовой выборке:**

| Метрика | Значение |
|---|---|
| **F1 (macro)** | **0.76** |
| Precision | 0.75 |
| Recall | 0.76 |
| Accuracy | 0.88 |

> Accuracy здесь малоинформативна из-за большого количества O-токенов (~85% текста). Основная метрика — F1.

**По типам сущностей:**

| Тип | Precision | Recall | F1 |
|---|---|---|---|
| DATE | 0.85 | 0.83 | 0.84 |
| PERSON | 0.82 | 0.84 | 0.83 |
| LOCATION | 0.78 | 0.79 | 0.78 |
| ORGANIZATION | 0.76 | 0.74 | 0.75 |
| CITY | 0.74 | 0.72 | 0.73 |
| COUNTRY | 0.71 | 0.69 | 0.70 |
| PROFESSION | 0.70 | 0.68 | 0.69 |
| EVENT | 0.65 | 0.62 | 0.63 |
| LAW | 0.58 | 0.55 | 0.56 |
| RELIGION | 0.52 | 0.48 | 0.50 |

Частые типы (PERSON, DATE, LOCATION) распознаются с F1 > 0.78. Редкие (LAW, RELIGION) — хуже из-за малого числа примеров.

## Эксперименты с гиперпараметрами

Проверено влияние `max_length`, `learning_rate` и `dropout`. Каждая конфигурация — 1 эпоха, оценка на тесте.

| Конфигурация | max_length | lr | dropout | F1 |
|---|---|---|---|---|
| **Базовая** | **128** | **2.5e-5** | **0.15** | **0.760** |
| Длинный контекст | 256 | 2.5e-5 | 0.15 | 0.738 |
| Высокий lr | 128 | 3e-5 | 0.15 | 0.744 |
| Комбинация | 256 | 3e-5 | 0.15 | 0.728 |
| Высокий dropout | 128 | 2.5e-5 | 0.30 | 0.698 |

**Вывод:** лучшая конфигурация — базовая (`max_length=128`, `lr=2.5e-5`, `dropout=0.15`). Увеличение контекста и повышение lr не дали прироста — тексты в NEREL короткие, а базовый lr уже оптимален.

---

## Ограничения

- **Редкие типы** (LAW, RELIGION, ORDINAL) — мало примеров в обучении, F1 < 0.60.
- **Вложенные сущности** — «мэр Киева» (PROFESSION + CITY) обрабатывается некорректно.
- **Длинные названия организаций** иногда разбиваются на несколько сущностей.
- **Accuracy не показательна** — доминируют O-токены.

## Установка и запуск

### Локально

```bash
# Установка uv
# Windows:
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
# Linux / macOS:
curl -LsSf https://astral.sh/uv/install.sh | sh

# Окружение и зависимости
uv venv
.venv\Scripts\activate        # Windows
source .venv/bin/activate     # Linux / macOS
uv pip install -r requirements.txt

# Запуск Jupyter
jupyter notebook
```

Открой `notebooks/experiments.ipynb` и выполни все ячейки.

### Через Docker

```bash
docker build -t nerel-ner .
docker run -p 8888:8888 nerel-ner
```

После запуска в консоли появится ссылка `http://127.0.0.1:8888/?token=...` — открой её в браузере.
